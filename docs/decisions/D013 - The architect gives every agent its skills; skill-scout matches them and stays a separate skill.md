# D013 — The architect gives every agent its skills; skill-scout matches them and stays a separate skill

## Context

Agent notes have carried a `skills:` field since the first version, and the
Claude Code renderer passes it on as preloaded skills. Nothing ever filled
it: the architect playbook never mentioned it and the templates ship
`skills: []`. Agents therefore started every task without the skills the
machine already had. Only Claude Code received the list at all.

The owner wrote skill-scout, a skill that splits a task into parts,
inventories every installed skill across tools, project and plugins (tagged by
who owns it), and proposes use, upgrade, browse or create per part, acting
only on approval. The question was whether it belongs inside the harness.

## Decision

**skill-scout stays a separate skill; the harness depends on it.** It answers
"which skills does this work need", which is useful in any folder without a
harness, and folding it in would make a one-minute question start the
harness's phases. The harness answers "which agent does this work" and now
asks skill-scout the other question at the points where it matters:

- **Architect, step 3:** each role is matched against the inventory; skills
  the agent uses on most tasks go on the library charter (portable) or the
  instance (project-only). Gaps become proposals for the user, never actions.
- **Optimize, skill pass:** ledger failures that share a method point at a
  thin or missing skill. Adding an installed skill to an agent is `auto`;
  upgrading, creating or installing one is always `ask`, because skills live
  outside the harness and are shared by other projects and tools.
- **Compile:** every target's prompt carries a "Skills" section, so tools
  without a preload field still see the list.

skill-scout is bundled as a fallback like llm-wiki (D012's rule: small,
stable, not generated by another tool), and `doctor` checks it.

## Consequences

A third bundled copy to keep in step with the skills repository; `doctor`
reports drift and now compares scripts as well as markdown. Compiled agents
that list skills grow by one short section. The harness never edits a skill:
changes to skills go through the user, then through the skills repository's
own rules.
