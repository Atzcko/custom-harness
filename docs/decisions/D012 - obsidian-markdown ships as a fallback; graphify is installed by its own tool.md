# D012 — obsidian-markdown ships as a fallback; graphify is installed by its own tool

## Context

D010 bundled only llm-wiki and left graphify and obsidian-markdown as
dependencies to be checked for, on the grounds that bundling third-party
skills raises licensing and update questions. The owner asked whether both
could simply travel with the harness so that a fresh machine needs no setup.
The two turned out to be different cases once their licences and update
mechanisms were checked.

## Decision

**obsidian-markdown is bundled**, under `bundled/obsidian-markdown/`, with its
MIT licence and an `UPSTREAM.md`. It is small and stable, because it documents
a file format, and the harness's own templates follow the two references it
carries for a vault that shares a directory with source code. Like llm-wiki it
is a fallback: the installer links it only where no copy is installed, and
`doctor` reports which copy is in use and whether the bundled one differs.

**graphify is not bundled.** Its skill file is generated by its own CLI with
`graphify install`, and the two are versioned together; a CLI newer than the
skill file produces a version-mismatch warning in the editor and the remedy is
to regenerate the skill. A static copy in the harness would therefore be the
cause of that warning after the first upgrade. Instead the installer offers
`--with-graphify`, which runs `uv tool install graphifyy && graphify install`,
and `doctor` prints those two commands when the skill is missing. Installing a
package on someone's machine stays opt-in.

## Consequences

Two bundled skills to keep in step with the owner's copies; `doctor` compares
them. A machine without graphify still cannot run the understand phase's graph
step until the owner runs one command, which is the price of never shipping a
stale generated file.
